## Canonical v0.5 targets

### 1. Durable long-running work — COVERED

**Implemented evidence**

- Phase 1 persists Goal / Flow / Task / Run / Decision / Change / Artifact / Verification state in SQLite with optimistic revisions, migrations, journaled events, restart recovery, and verification-gated completion.
- Phase 7 adds bounded retry/resume/escalation, loop detection, quarantine, and durable retry accounting rather than an endless live process.
- Phases 31–43 add governed production planning, dependency readiness, preparation, dispatch claims/executions, recovery admission, and a fixed bounded Manager driver whose work is reconstructable from durable state.
- Phases 45–46 add explicit durable Goal-bootstrap authority with separate fresh-start/recovery semantics and no automatic Planner replay after uncertainty.
- Phase 47 extends the same durable claim/execution/no-replay law to deterministic simulation production dispatch.

**Release assertion**

A process may stop between bounded actions without erasing committed production authority/evidence. Restart reconstructs state from repository + `.origin-forge` rather than requiring a chat transcript or one immortal Manager process.

**Residual risk / boundary**

v0.5 does not promise instruction-pointer continuation, a daemon, or automatic queue draining. Recovery remains explicit and state-based.

---

### 2. Local coding models — COVERED

**Implemented evidence**

- Phase 2 provides replaceable local model adapters and llama.cpp-compatible bounded local HTTP execution for proposal-only coding work.
- Worker model output is a structured hash-preconditioned proposal and has no repository write or self-verification authority.
- Phase 14 adds governed model profiles, semantic roles, explicit fallback policy, resource scheduling, runtime-loader ownership, and Run-level model/resource evidence.
- The bounded coding attempt remains isolated Workspace → proposal → apply → audit → sandbox verification rather than direct model mutation.

**Release assertion**

Local coding models can participate through replaceable governed adapters without becoming project truth, filesystem authority, or verification authority.

**Residual risk / boundary**

Operators still configure approved local runtimes/models. v0.5 does not bundle model weights or silently download/activate them.

---

### 3. Governed Skills + Skill evaluation — COVERED

**Implemented evidence**

- Phase 9 provides instruction-only project Skills with deterministic selection, semantic versions, fingerprints, provenance, hard catalog/read/instruction budgets, and no executable Skill authority.
- Phase 12 provides immutable evaluation cases, fixture/scorer/environment identity, paired with-vs-without trials, stable seeds, regression-dominant verdicts, raw cost/outcome evidence, content-addressed reports, and replayability.
- Phase 26 Workshop may consume exact trusted Phase-12 evidence for promotion eligibility but cannot activate a Skill itself.

**Release assertion**

Procedural knowledge can be selected and measured without allowing Skill text or evaluation output to grant new production authority.

**Residual risk / boundary**

Promotion/activation remains a separate governed decision; benchmark improvement is not automatic deployment authority.

---

### 4. Structural / LSP code intelligence — COVERED

**Implemented evidence**

- Phase 10 provides bounded deterministic Python AST indexing and structural context expansion over an isolated Workspace.
- Phase 11 adds provider-neutral read-only code intelligence, bounded LSP JSON-RPC, portable position conversion, Workspace URI containment, normalized definitions/references/symbols/diagnostics, and trusted configured Podman language servers.
- Diagnostics remain supplementary evidence and never become correctness truth.

**Release assertion**

Origin Forge can enrich context with structural and LSP evidence without recursively dumping a repository or giving the model unrestricted language-server control.

**Residual risk / boundary**

Only configured supported servers/providers are admitted; native-host arbitrary LSP execution is not a v0.5 promise.

---

### 5. Progressive tool discovery — COVERED

**Implemented evidence**

- Phase 13 provides content-addressed governed tool catalogs, authority-filtered search, bounded `search_tools` / `describe_tool`, schema hydration budgets, hidden/unknown denial equivalence, and disclosure-footprint metrics.
- Tool discovery intentionally omits a generic model-facing `call_tool` authority.

**Release assertion**

Authorized tool contracts can be progressively disclosed without loading the entire catalog or turning discovery into execution authority.

**Residual risk / boundary**

A discovered descriptor is information, not permission to execute an arbitrary operation.

---

### 6. Model / resource scheduling — COVERED

**Implemented evidence**

- Phase 14 provides process-local atomic CPU/RAM/GPU leases, VRAM headroom, compute slots, exclusive/pinned GPU semantics, deterministic best-fit placement, explicit static incompatibility vs contention, model profiles/roles, explicit fallback chains, and model load/use/unload ownership.
- No implicit downgrade or hidden contention queue is introduced.
- Inspection remains read-only; durable Task/Run state remains authoritative when ephemeral leases disappear on restart.

**Release assertion**

Origin Forge can select and safely schedule governed local model/resource profiles without silently changing model quality or making resource leases durable production truth.

**Residual risk / boundary**

Hardware availability is environmental; v0.5 guarantees bounded admission/ownership semantics, not that every configured model fits every machine.

### 7. Offline memory consolidation and audited improvement proposals — COVERED

**Implemented evidence**

- Phase 15 Dream Cycle freezes completed-work evidence, preprocesses staleness/duplication, emits proposal-only candidates, independently audits them, and constructs immutable audit-bound memory generations without rewriting canonical source/Task truth.
- Phase 26 Workshop freezes candidates/evaluation plans and produces regression-dominant trusted evaluation plus promotion-eligibility evidence only.
- Phase 27 programmatic context experiments provide bounded content-addressed read-only programs, exact replay/evaluation, and no generic mutation language.
- Phase 29 training/fine-tuning research freezes trusted datasets/plans/evaluation and produces research evidence without checkpoint activation/model replacement authority.

**Release assertion**

Origin Forge can learn from completed work and measure candidate improvements while keeping consolidation/research offline, bounded, auditable, and non-self-activating.

**Residual risk / boundary**

No live self-modification, automatic memory/Skill/routing promotion, checkpoint activation, or production weight replacement is authorized.

### 8. Specialist review — COVERED

**Implemented evidence**

- Phase 16 provides isolated evidence-bound Reviewer contracts, exact frozen packages, one-shot model execution, infrastructure-owned finding/report identity, independent structural report audit, immutable persistence, and replayable evaluation.
- Reviewer scratch/context is isolated from Executor session state.
- Reviewer findings remain advisory evidence and do not directly block/complete Tasks or repair source.

**Release assertion**

A fresh specialist can review bounded exact evidence without becoming a peer agent with production mutation or verification authority.

**Residual risk / boundary**

Only the measured Reviewer role is implemented; broader specialist roles remain future work unless separately justified.

### 9. Project graph + Design Bible — COVERED

**Implemented evidence**

- File-binding currentness is inspected without rewriting canonical bindings.
- Project Intelligence is canonical infrastructure state; model inference remains proposal/evidence only.

**Release assertion**

Stable product meaning and Design Bible constraints can survive implementation changes and be inspected independently of a model rediscovering the project graph each session.

**Residual risk / boundary**

No automatic model-generated graph discovery/promotion or source mutation is implied by graph availability.

### 10. Cryptographic provenance — COVERED

**Implemented evidence**

- Phase 18 provides company-root trust identity, Ed25519 operational certificates/signatures, revocation, signed provenance manifests, protected public persistence, offline trust verification, and artifact-currentness separation.
- Secret key material remains outside media/runtime/model authority.
- Later cross-media fingerprints/watermarks remain supplementary evidence and never replace the Phase-18 trust root.

**Release assertion**

Accepted governed Artifacts can carry cryptographically verifiable provenance bound to causal production evidence without treating signatures as current verification or semantic correctness.

**Residual risk / boundary**

Signing remains explicit; v0.5 does not auto-sign every output or expose secret keys through production adapters.

### 11. Basic 2D production — COVERED

**Implemented evidence**

- Phase 19 provides canonical bounded sprite/project/layer/frame/animation/palette/pixel contracts, deterministic PNG validation/encoding, isolated `MEDIA-*` workspaces, strict one-shot bridge execution, containment/output revalidation, media Run/Artifact/Verification evidence, and create-only governed adoption.
- Real pinned Pixelorama v1.2 export evidence exists behind the reviewed boundary.
- Phase 21 later adds governed image-generation/editing and advisory vision evidence without weakening the Phase-19 2D trust/adoption boundary.

**Release assertion**

Origin Forge can produce and independently validate bounded 2D raster evidence and explicitly adopt verified new output without overwrite, signing, or Task-completion shortcuts.

**Residual risk / boundary**

The release does not claim a polished interactive editor workflow, automatic asset adoption, or unrestricted GUI/editor scripting.

## Cross-cutting release assertions

The v0.5 release candidate must preserve all of the following:

1. **Durable state over process/chat lifetime.** Production truth is reconstructable without a long conversation or daemon.
2. **Models propose; independent evidence verifies.** No model output validates itself.
3. **Known-good source isolation.** Bounded coding/media work occurs behind existing Workspace/adoption boundaries.
4. **Bounded continuation.** Attempts, Manager advancement, Planner uncertainty, and simulation execution obey explicit budgets/no-replay law.
5. **Reconstructable context/authority.** Skills, tools, planning, routing, binding, claims, execution and evidence are content/revision bound.
6. **Explicit operator authority.** No release packaging creates automatic mutation/merge/release authority.
7. **Causal/provenance evidence remains inspectable.** Release documentation does not replace durable state or cryptographic trust.
8. **Historical v0.1 remains immutable.** v0.5 gets separate readiness/operator/acceptance records and never moves the `v0.1.0` tag.
