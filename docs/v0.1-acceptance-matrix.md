# v0.1 Acceptance Matrix

Status: **FINAL v0.1.0 CANDIDATE TRACEABILITY — exact-head CI pending**

This matrix maps the canonical roadmap's v0.1 success criteria to implemented Origin Forge mechanisms. It is release traceability, not a new authority source: the referenced subsystems and their own verification evidence remain authoritative.

## Canonical success criteria

### 1. No dependency on long chat history

**Implemented evidence**

- Phase 1 durable Goal / Flow / Task / Run / Verification state makes production state independent of a chat transcript.
- Phase 8 deterministic source-context discovery reconstructs source context from durable Task evidence and an isolated workspace.
- Phase 9 governed Skills are selected and fingerprinted from durable state rather than conversation memory.
- Phase 15 Dream/memory stores bounded derived memory as explicit audited artifacts instead of private hidden conversation state.
- Phase 27 programmatic context reconstructs bounded context from content-addressed read-only programs and packages.

**Release assertion**

A fresh process can determine current production state and reconstruct governed context from repository + `.origin-forge` state without possessing the conversation that created it.

**Residual release risk**

Documentation/examples must not imply that a chat transcript is required to resume work.

---

### 2. Process restart does not lose work state

**Implemented evidence**

- Phase 1 persists project/control-plane state in SQLite.
- runtime recovery explicitly identifies and reconciles interrupted RUNNING records rather than silently treating them as complete.
- later evidence stores use immutable no-overwrite persisted records for provenance, Dream/memory, simulation, Workshop, context experiments, fingerprints, and training research.

**Release assertion**

A process restart may interrupt active execution, but it does not erase previously committed durable production/evidence state; interrupted execution is represented explicitly.

**Residual release risk**

v0.1 does not promise live-process continuation at an instruction pointer. It promises durable state/recovery semantics.

---

### 3. Known-good project state remains isolated

**Implemented evidence**

- Phase 3 established isolated Git workspace/worktree application.
- patch proposals are applied away from the user's known-good checkout before independent audit.
- media/runtime integrations use protected isolated workspaces and create-only governed adoption rather than in-place mutation.
- Phase 30 is read-only and refuses to become a hidden mutation path through the UI.

**Release assertion**

Proposed autonomous changes do not require mutating the known-good working tree before validation/adoption.

**Residual release risk**

External tools remain governed per adapter; release docs must not suggest arbitrary direct editor/shell access.

---

### 4. Model cannot self-verify completion

**Implemented evidence**

- the core architecture separates Executor proposal from independent Verification/Audit authority.
- Phase 4 separates `AUDITED` from `VERIFIED` and defines backend-neutral verification contracts.
- sandbox/tool validators, media validators, runtime observation, playtesting, simulation, provenance, Workshop evaluation, and training-research evaluation all retain infrastructure-owned acceptance semantics.
- model/Dream/vision/playtest/simulation/workshop/fingerprint/training outputs never acquire Task completion authority merely by producing a positive result.

**Release assertion**

No model response is sufficient evidence for its own production Task completion.

**Residual release risk**

Human operators can still record explicit verification through governed interfaces; that human authority must not be confused with model self-verification.

---

### 5. Retries and no-progress loops are bounded

**Implemented evidence**

- Phase 7 implements bounded retry/resume/escalation policy with configured retry ceilings.
- Phase 25 simulation records no-progress/stall evidence using deterministic whole-step state change.
- Phase 26/27/29 experiments use frozen budgets/resource ceilings rather than open-ended self-improvement loops.

**Release assertion**

Origin Forge does not rely on an unbounded retry loop to eventually declare success.

**Residual release risk**

Individual external adapters may have their own timeouts/bounds; v0.1 documentation should keep those as governed subsystem limits rather than a global guarantee of equal ceilings.

---

### 6. Selected context is reconstructable

**Implemented evidence**

- Phase 8 context selection is deterministic from durable Task terms and isolated tracked source state.
- Phase 9 records selected Skill fingerprints/bundles.
- Phase 27 records exact request/catalog/program/execution/context-package hashes and deterministic replay classification.
- causal state and Artifact records preserve the evidence needed to explain which governed inputs were used.

**Release assertion**

For governed context paths, the system records enough deterministic identity/evidence to reconstruct or audit what context was selected rather than relying on hidden prompt assembly.

**Residual release risk**

Not every historical model invocation predating later context phases has identical richness; the claim is about the governed v0.1 paths, not retroactive enrichment of every legacy record.

---

### 7. Final diff is understandable

**Implemented evidence**

- Phase 3 deterministic patch application and independent content audit preserve explicit proposed/applied change structure.
- Decisions and Changes provide causal summaries and before/after references.
- Phase 17 Project Intelligence/Design Bible adds stable semantic project meaning and bounded impact queries.
- Phase 30 exposes Decision → Change → Artifact → Verification history in a human-facing read-only cockpit.

**Release assertion**

A reviewer can inspect the causal change chain and repository diff without needing hidden model reasoning to understand what changed and why.

**Residual release risk**

“Understandable” remains partly human judgment; v0.1 guarantees explicit diff/causal evidence, not that every large change is intrinsically easy to review.

---

### 8. Meaningful changes have causal/provenance records

**Implemented evidence**

- Phase 1 establishes Goal/Flow/Task/Run/Decision/Change/Artifact causal lineage.
- later media/runtime integrations publish typed Artifact/Verification evidence rather than opaque side effects.
- Phase 18 binds accepted Artifacts to Ed25519 provenance manifests and operational trust identity.
- Phase 28 adds supplementary cross-media fingerprints while explicitly keeping Phase-18 cryptographic provenance as the trust root.
- Phase 30 exposes causal and provenance metadata without acquiring signing/trust authority.

**Release assertion**

Meaningful governed production outputs can be traced to durable causal state and, where provenance is issued, cryptographically bound provenance records.

**Residual release risk**

Fingerprint/watermark evidence is supplementary and must never be represented as authorship or signature proof.
